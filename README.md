# 渠道时效管理后台

中航环球渠道时效系统的独立管理端。前端使用 React、TypeScript、Ant Design 与 Tailwind CSS；服务端使用 Node.js、Fastify 和 PostgreSQL。生产访问域名为 [effective.omfreight.vip](https://effective.omfreight.vip)，对应的公开时效系统为 [transit.omfreight.vip](https://transit.omfreight.vip)。

本仓库提供真实业务数据库适配、管理员登录、数据维护与展示控制，同时保留明确标注的本地 SQLite 演示模式。生产模式不会回退到演示数据，也不会在启动时自动建库、导入或迁移。

## 业务能力与规则

- 柜子运输生命周期：装柜、实际开船、到港、卸船、可提柜、提柜、拆柜。柜号可以重复，每次运输有独立身份。
- 公司渠道与具体航线分开管理；航线包含船公司、起运港、目的港和参考时效。
- 亚马逊仓库与送仓批次独立管理，同柜同仓允许多批。预计送仓与实际送仓分别记录。
- 保留多次查验、起止日期和独立状态。历史日期未知时留空，不能仅凭缺少结束日期推断“查验中”。
- 柜子、航线、仓库和批次分别控制展示；新记录默认不展示。启用与发布开关都生效，发布不能绕过原有有效性、海运、非取消和实际日期条件。
- 业务更正记录操作者、原因、采用来源与字段锁定；编辑版本冲突会拒绝覆盖。生产删除是归档 / 取消，不物理删除原始运输、批次或证据。

柜子和航线时效到“拆柜”结束，亚马逊时效到每批实际送仓结束。“清单完整”与“全部送完”分别判断。未知数量、日期、柜型、航线名称和时效不会填成 0 或猜测值。

## 本地开发与验证

需要 Node.js 22.13 以上版本；部署配置使用服务器已有的 Node.js 24 运行时。

```sh
npm ci
npm run dev:api
npm run dev
```

API 默认监听 `127.0.0.1:3102`，开发页面为 `http://127.0.0.1:4180`。未指定生产模式时，独立演示数据保存在 `.data/admin.sqlite`；首次初始化写入合成数据，之后保留编辑结果。这个模式不连接生产数据库。

```sh
npm run typecheck
npm test
npm run build
npm run package
```

测试包括本地 API、身份与来源边界，以及在隔离 PGlite 数据库中执行完整历史迁移后的生产仓库测试。生产测试使用真实权限配置，核对迁移前后原始列完全相同、展示条件、人工来源与审计、未知值、质量状态、跨租户关联、版本冲突和归档保留。

`npm run package` 生成 `artifacts/` 下的发布包及 SHA-256 校验文件，不包含业务数据、凭据、本机 SQLite 或 `.private/` 验证材料。

## 生产配置与目录

| 位置 | 用途 |
| --- | --- |
| `/opt/freight-admin/releases/` | 独立版本发布目录 |
| `/opt/freight-admin/current` | 当前版本链接，systemd 的工作目录 |
| `/etc/freight-admin/api.env` | 生产配置，只允许 root 读取 |
| `/etc/freight-admin/stage.env` | 隔离预发布配置，只允许 root 读取 |
| `/etc/systemd/system/freight-admin.service` | 管理端服务，使用 `freight-admin` 非特权用户 |
| `/var/log/nginx/freight-admin.*.log` | 管理域名的 Nginx 日志 |
| `.private/` | 本机私有凭据及业务验证材料，禁止提交 |

生产环境需要 `NODE_ENV=production`、`ADMIN_SOURCE=postgres`、`ADMIN_ORIGIN=https://effective.omfreight.vip`、`ADMIN_TENANT=szzhhq`、`ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH`、`ADMIN_SESSION_SECRET`、`DATABASE_URL` 和 `PORT=3102`。字段示例见 `.env.example`；不能把真实值写进仓库、日志、浏览器代码或命令行参数。

`ADMIN_PASSWORD_HASH` 使用应用提供的 scrypt 哈希格式。`scripts/provision-environment.mjs` 是首次部署工具：从受限凭据文件读取用户名和密码，生成独立数据库密码与会话密钥，创建受限环境文件，然后删除输入凭据文件。已有配置时会拒绝覆盖。后续更新应保留这些环境文件，不应重复运行初始化工具。环境文件交给 systemd 读取，不要当作 shell 脚本执行。

应用只监听本机地址，由 Nginx 提供 HTTPS。代理覆盖真实来源地址，服务只信任本机代理。登录会话使用 Secure、HttpOnly、SameSite=Strict Cookie，有效期为 8 小时；修改数据还必须来自配置的管理域名。登录尝试有速率限制。当前使用一个配置的管理员账户；服务重启会清空进程内会话，需要重新登录。

## 数据库迁移与发布流程

现有生产数据库为 `freight_times`，业务表位于 `freight` schema。管理迁移为 `database/009_admin.sql`，权限为 `database/admin_role.sql`。`database/baseline/` 仅用于隔离测试，**不能在已有生产库重放，也不能把初始导入重新当作同步执行**。

1. **记录基线并备份。** 在修改前保存 PostgreSQL 自定义格式备份、备份校验值，以及运输、批次、异常、来源、字段候选、路由事件、复核事项和审计的行数与按稳定主键排序的原始列校验值；记录已发布数量和现有公开查询的柜子 / 亚马逊样本集合或校验值。私有结果放在受限路径，不进入 Git。
2. **恢复到隔离数据库。** 实际恢复备份后核对基线，仅查看备份目录不算恢复验证。预发布服务使用独立数据库、独立环境文件和本机端口 3104。
3. **只在预发布库先迁移。** 由数据库管理员执行 `009_admin.sql`，再执行 `admin_role.sql`；检查 `freight_admin.migrations` 版本为 9。迁移只新增管理字典、关联、审计和显示门控，保留原业务列及发布状态。旧字典 / 批次门控初始允许原先已获准展示的数据，新记录门控默认关闭。
4. **核对迁移不改变业务数据。** 将原始列、行数、发布状态及公开样本集合与迁移前比较；检查专用 `freight_admin_api` 角色可完成所需操作，不能修改历史质量标志、删除业务记录或改删审计。应用使用该角色，不使用数据库超级用户。
5. **运行隔离写入验证。** 执行下方预发布验证，覆盖新增、编辑、查验、批次、门控、版本冲突、审计及归档。测试只创建独立 `QATEST` 记录；这些记录及归档历史留在隔离数据库中，不写进生产。
6. **准备并切换发布版本。** 验证发布包校验值，安装生产依赖，按 `deploy/` 模板配置服务和 HTTPS。重新确认生产备份与基线后，显式执行已验证的迁移和权限配置，再切换 `current` 并启动服务。应用启动只检查结构，不执行迁移。
7. **生产只读验收。** 验证管理员登录、未登录边界、数据库健康、数据数量、公开门控和退出登录；再次核对原始业务值、发布状态及公开时效查询，确认管理界面能读取真实数据。

迁移把现有 `freight.valid_container_metrics` 和 `freight.valid_amazon_delivery_metrics` 保留为相同列结构，并添加稳定的展示门控。现有公开 API 本来就查询这两个视图，因此航线、仓库和批次开关会影响线上前台；原有质量筛选、租户隔离与发布时间条件继续生效。公开应用不会获得管理表、内部备注或审计的读取权限。管理端展示预览采用相同的有效指标和日期屏蔽规则，原始编辑字段仍保留实际录入值。

为让软取消保留实际送仓日期，迁移调整了一条旧约束，使已取消批次可以保留已有实际日期。迁移不修改任何既有日期。更详细的字段映射、权限与人工来源规则见 `database/README.md`。

## 预发布和生产验收

凭据文件只包含管理员用户名和密码，应放在权限受限的文件中。验证脚本不打印凭据、Cookie、业务标识或响应正文。

隔离预发布写入检查需要同时提供隔离标志和本机地址；缺少任一条件会拒绝运行：

```sh
ADMIN_STAGING_ISOLATED=1 BASE_URL=http://127.0.0.1:3104 \
  node scripts/verify-admin.mjs --credentials /secure/admin-login.json --staging-write
```

生产验证不修改业务记录：

```sh
BASE_URL=https://effective.omfreight.vip \
  node scripts/verify-admin.mjs --credentials /secure/admin-login.json
```

`GET /api/health` 每次检查数据库连接和迁移状态；管理数据及展示预览需要登录。查看故障日志时可使用 `journalctl -u freight-admin` 和 Nginx 的管理端日志，但不能输出环境文件或数据库连接串。

## 回退与维护边界

发现问题时，先停止或禁用管理服务并让管理域名返回维护页面，保存当前数据库状态、日志和审计。仅代码回归且数据库结构兼容时，可以把 `current` 切回上一发布目录后重新启动；这不会撤销已提交的业务更正。

不要通过删除 `freight_admin` schema 或盲目恢复旧备份来回退应用。新开关可能已经控制了公开数据，新的更正也可能已经产生审计。若必须回退视图或迁移，需要另行审阅当前门控和变更历史，明确公开展示的预期，并验证回退前后的样本与权限。数据库恢复必须基于确认的恢复点和数据保留方案。

管理界面当前读取最近 200 条操作日志；完整追加历史保存在数据库中。当前没有建设持续源系统采集或增量同步。未来同步需要维护新的管理关联、遵守人工字段锁定、保留旧来源并保持新记录默认不展示。后台纠正一个历史无效日期不会自动解除原有质量标记或复核事项；这需要独立的显式质量复核。未确认目的地、非亚马逊、汇总和重复来源仍保留在原库中，不会因为后台仅展示确认的亚马逊批次而被删除或重新分类。
